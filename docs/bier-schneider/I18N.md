# Mehrsprachigkeit (i18n)

Es gibt zwei getrennte Systeme, weil die Zielgruppen verschieden sind:

| Bereich                                                      | Sprachen                                                    | Technik                                                      |
| ------------------------------------------------------------ | ----------------------------------------------------------- | ------------------------------------------------------------ |
| **Bewerbung** (`/apply`, Stellenseite `/jobs`)               | 9 (DE, Leichte Sprache, EN, PL, RO, UK, RU, TR, AR mit RTL) | `features/quick-apply/messages.ts`, Sprache pro Bewerbung    |
| **Arbeitgeberbereich** (Dashboard, Anmeldung, Einstellungen) | Deutsch und Englisch                                        | [next-intl](https://next-intl.dev) (MIT), Sprache pro Person |

Dieses Dokument beschreibt den Arbeitgeberbereich. Die Bewerbung ist in
[PRD.md](PRD.md) §5.3 beschrieben und bleibt unverändert.

## Welche Sprache wird angezeigt?

1. Eigene Wahl im Nutzermenü (Avatar oben rechts → „Deutsch | English“). Sie steht im
   Cookie `HARLY_LOCALE` (ein Jahr gültig).
2. Ohne Wahl: die Browsersprache (`Accept-Language`). `de-*` → Deutsch, `en-*` → Englisch.
3. Sonst Deutsch.

URLs ändern sich nicht (keine Präfixe wie `/en/...`). Datumsangaben werden immer in der
Zeitzone `Europe/Berlin` formatiert, damit Server und Browser gleich rechnen.

## Aufbau

```text
apps/web/
├── messages/
│   ├── de/<bereich>.json     # z. B. jobs.json, candidates.json
│   └── en/<bereich>.json     # gleiche Schlüssel wie de/
└── src/i18n/
    ├── config.ts             # Sprachen, Cookie, Browser-Erkennung
    ├── messages.ts           # bindet alle JSON-Dateien ein (+ Typen)
    ├── request.ts            # next-intl: Sprache je Anfrage
    ├── actions.ts            # Server-Action zum Umschalten
    ├── next-intl.d.ts        # typsichere Schlüssel
    ├── test-utils.tsx        # withIntl() für Tests
    ├── ../test/setup-intl.ts # getTranslations() & Co. in Vitest (Englisch)
    └── messages.test.ts      # Parität DE/EN, keine leeren Texte, gleiche Platzhalter
```

Jeder Bereich hat **eine eigene Datei** pro Sprache. So können mehrere Personen
gleichzeitig übersetzen, ohne sich in die Quere zu kommen. Neue Bereiche werden nur in
`src/i18n/messages.ts` ergänzt.

## So wird übersetzt

### Client-Komponente

```tsx
"use client";
import { useTranslations } from "next-intl";

export function SaveBar() {
  const t = useTranslations("jobs.editor");
  const tc = useTranslations("common.actions");
  return <button type="submit">{tc("save")}</button>;
}
```

### Server-Komponente, Server-Action, `generateMetadata`

```ts
import { getTranslations } from "next-intl/server";

const t = await getTranslations("jobs");
return { title: t("pageTitle") };
```

### Zahlen, Daten, Mehrzahl

Nie selbst formatieren:

```tsx
const format = useFormatter(); // Server: await getFormatter()
format.dateTime(date, { dateStyle: "medium" });
format.relativeTime(date);
t("candidateCount", { count }); // "{count, plural, one {# Bewerbung} other {# Bewerbungen}}"
```

Nicht mehr verwenden: `toLocaleDateString("en-US")`, `date-fns`-`format` mit festen
englischen Mustern, `"en-US"` in `Intl.*` – stattdessen `useFormatter`/`getFormatter`.

## Regeln für Texte

- **Schlüssel** auf Englisch in camelCase, nach Ort gruppiert:
  `candidates.detail.actions.reject`. Allgemeines steht in `common` (Speichern,
  Abbrechen, Rollen …) und wird nicht dupliziert.
- **Englisch** ist Harlys bisheriger Text, unverändert übernommen.
- **Deutsch**: natürlich, kurz, „Sie“ vermeiden durch neutrale Formulierungen
  (Schaltflächen im Infinitiv: „Speichern“, „Kandidat hinzufügen“). Fachbegriffe wie
  im PRD: Bewerbung, Stelle, Stufe, Pipeline, Talentpool, Arbeitsbereich.
  Geschlechtergerecht mit Schrägstrich („Recruiter/in“), wo nötig.
- **Platzhalter** im ICU-Format (`{name}`), in beiden Sprachen gleich. Keine Sätze aus
  Teilen zusammensetzen – lieber ein ganzer Satz mit Platzhaltern.
- Auch **unsichtbare** Texte übersetzen: `aria-label`, `title`, `placeholder`, `alt`,
  Toasts, Bestätigungsdialoge, Fehlermeldungen aus Server-Actions.
- **Nicht** übersetzen: Daten aus der Datenbank (Stellentitel, Namen, eigene
  Stufennamen), Markennamen, Code/IDs.

## Prüfungen

| Prüfung                        | Wo                                                     |
| ------------------------------ | ------------------------------------------------------ |
| gleiche Schlüssel in DE und EN | `src/i18n/messages.test.ts` (`pnpm --filter web test`) |
| keine leeren Texte             | ebenda                                                 |
| gleiche Platzhalter            | ebenda                                                 |
| existiert der Schlüssel?       | TypeScript (`pnpm typecheck`) über `next-intl.d.ts`    |
| keine Klartexte im JSX         | ESLint-Regel `employer-ui-i18n` für fertige Bereiche   |

Einen Bereich vor dem Eintragen in `EMPLOYER_UI` (`apps/web/eslint.config.mjs`) prüfen:

```bash
cd apps/web
EMPLOYER_I18N_EXTRA="src/features/jobs/**/*.tsx" pnpm exec eslint src/features/jobs
```

**Tests:** Server-Code (`getTranslations`, `getFormatter`, `getLocale`) bekommt in
Vitest automatisch die englischen Texte (`src/test/setup-intl.ts`), bestehende
englische Erwartungen bleiben gültig. Client-Komponenten in Tests mit
`withIntl(<Komponente />, "de" | "en")` aus `src/i18n/test-utils.tsx` rendern.

In Storybook schaltet die Sprach-Leiste mit: „English“ zeigt den Arbeitgeberbereich
auf Englisch, alle anderen Sprachen auf Deutsch.
